1CSS 变量 — 一次定义，到处使用

核心概念: :root 和 var()

传统写法里，每个颜色要在几十个地方重复写。如果设计师说"把主色改一下"， 你得逐个修改，非常容易遗漏。CSS 变量就是为了解决这个问题。

类比：就像你家里所有的灯都接到一个总开关上——拧一下总开关，所有灯都变了。 定义一次变量，所有用到 var(--变量名) 的地方自动更新。 
/* :root 是 CSS 的"根"，写在 :root 里的变量全局可用 */
:root {
  --bg-primary:    #1a1a2e;     /* 主背景色 */
  --accent:        #e94560;     /* 强调色（按钮/标题） */
  --radius:        8px;         /* 统一圆角大小 */
  --transition:     0.2s ease;   /* 统一过渡动画速度 */
}

/* 使用时用 var(--变量名) 引用 */
.btn {
  background: var(--accent);    /* 自动取 #e94560 */
  border-radius: var(--radius); /* 自动取 8px */
}
命名规范：变量名用两个短横线开头 --xxx， 单词之间用短横线连接。这叫 kebab-case（烤肉串命名法）。

2Flexbox 弹性布局 — 自动排列的秘密

核心概念: display: flex 和 gap

在 Flexbox 出现之前，要让几个元素横排，只能用 float 或者 inline-block， 经常出现各种对齐问题。Flexbox 提供了一个"弹性容器"，里面的元素会自动排列。

类比：Flex 容器像一个智能书架，你放几本书进去它会自动给你排列整齐、 均匀分布空间。你只需要说"横着排"还是"竖着排"。 
/* Flexbox 布局的三个关键属性 */
.container {
  display: flex;              /* 1. 开启弹性布局 */
  flex-direction: row;        /* 2. 主轴方向: row(横) / column(竖) */
  gap: 10px;                /* 3. 子元素之间的间距 */
}

/* flex: 1 让元素自动撑满剩余空间 */
.input-box {
  flex: 1;   /* 可以理解为"占满剩余所有宽度" */
}

在我们的待办清单中，整个页面是一个大的竖排 Flex 容器， 输入框区域是横排 Flex，筛选标签栏也是横排 Flex。

3HTML 语义化结构 — 让代码会说话

核心概念: 用正确的标签描述内容

很多人用 <div> 包一切，这会让代码难以阅读。 语义化标签 告诉浏览器和读代码的人：这段内容是什么。

好处：① 代码更易读 ② 搜索引擎更友好 ③ 屏幕阅读器（盲人用）能理解结构 
<!-- 语义化的页面骨架 -->
<header>    <h1>待办清单</h1>  </header>    <!-- 页头 -->
<form>      输入框 + 按钮          </form>     <!-- 表单（天然支持 Enter 提交） -->
<nav>       筛选标签              </nav>      <!-- 导航 -->
<ul>        任务列表              </ul>       <!-- 列表 -->
<footer>    计数 + 清除按钮         </footer>   <!-- 页脚 -->
关键细节：我们用 <form> 包住输入框和按钮， 而不是 <div>，因为 <form> 天然响应 Enter 键提交， 不需要额外写键盘监听代码。

4CSS 伪类和过渡 — 让界面"活"起来

核心概念: :hover :focus 和 transition

纯静态界面让人感觉"死板"。伪类可以在特定状态下触发样式变化， 过渡让变化平滑，不会突然跳变。 

/* :hover — 鼠标悬停时 */
button:hover {
  background: #ff6b81;  /* 颜色变亮 */
}

/* :focus — 输入框获得焦点时 */
input:focus {
  border-color: #e94560;  /* 边框变红 */
}

/* transition — 让变化平滑过渡 */
button {
  transition: background 0.2s ease;
  /* 解读: 当 background 改变时，用 0.2 秒平滑过渡 */
}
为什么 0.2 秒？ 人类感知"即时反馈"的阈值大约是 0.1-0.2 秒。 太短感觉不到过渡效果，太长会觉得拖沓。

5响应式设计 — 手机电脑都能用

核心概念: @media 媒体查询

@media 让你可以根据屏幕宽度应用不同的样式。 这叫"断点"——在某个宽度以下，切换到移动端布局。 

/* 屏幕宽度小于 480px 时生效（即手机屏幕） */
@media (max-width: 480px) {
  body      { padding: 16px 8px; }    /* 减小边距 */
  h1        { font-size: 24px; }      /* 缩小标题 */
  .row      { flex-direction: column; } /* 改为竖排 */
  button    { width: 100%; }          /* 按钮撑满 */
}
移动端优先原则：先写好手机版的布局，再用 @media (min-width: xxx) 逐步增强大屏体验。本项目用 max-width: 480px 作为手机断点。

6DOM 操作 — JavaScript 操控页面元素

核心概念: document.getElementById 和 innerHTML

DOM（Document Object Model）是浏览器把 HTML 转换成的"对象树"。 通过 JavaScript，你可以找到任意元素、读取/修改它的内容、甚至创建新元素。 

// 1. 找到元素 — 通过 ID 获取
var input = document.getElementById("todo-input");

// 2. 读取值
var text = input.value;   // 获取用户输入的文字

// 3. 修改值
input.value = "";           // 清空输入框

// 4. 创建新元素并插入页面
var li = document.createElement("li");
li.innerHTML = '<span>新任务</span>';  // 设置内部 HTML
list.appendChild(li);                // 追加到列表末尾
innerHTML vs textContent： innerHTML 会把内容当 HTML 解析（有 XSS 风险）， textContent 只当纯文本处理（安全但无法插入标签）。 本项目用自定义的 escapeHTML() 函数先转义再拼接，确保安全。

7事件与事件委托 — 用户交互的核心

核心概念: addEventListener 和事件冒泡

事件 是用户操作（点击、按键、鼠标移动等）触发的信号。 事件委托 是一种优化技巧：不在每个子元素上绑定事件， 而是在父元素上绑定一个事件，利用"冒泡"机制统一处理。 

// 事件委托：只在列表上绑定一个 click，处理所有子元素
list.addEventListener("click", function(e) {
  var target = e.target;         // e.target 是实际被点击的元素

  // closest() 向上查找最近的 .todo-item 祖先
  var li = target.closest(".todo-item");

  // 判断被点击的是什么
  if (target.classList.contains("todo-delete")) {
    deleteTask(id);   // 点了删除按钮
  }
  if (target.classList.contains("todo-checkbox")) {
    toggleTask(id);   // 点了复选框
  }
});
为什么用事件委托？ 如果每添加一个任务就绑定一个新的事件， 1000 个任务就有 1000 个监听器，内存和性能都会变差。委托只需要 1 个监听器。

冒泡机制： 点击一个子元素，事件会像气泡一样一层层向上传递到父元素， 直到 document。这就是"事件冒泡"。

8数组方法 — filter / find / forEach

核心概念: 遍历数组的三种常用方法

JavaScript 提供了多个数组方法来代替传统的 for 循环， 代码更简洁、意图更清晰。 

var tasks = [
  { id: "a1", text: "买牛奶", completed: false },
  { id: "b2", text: "写作业", completed: true  },
  { id: "c3", text: "跑步",   completed: false },
];

// filter — 筛选出符合条件的，返回新数组（不修改原数组）
var active = tasks.filter(function(t) { return !t.completed; });
// 结果: [买牛奶, 跑步]

// find — 找到第一个符合条件的，返回该元素
var task = tasks.find(function(t) { return t.id === "b2"; });
// 结果: { id: "b2", text: "写作业", completed: true }

// forEach — 对每个元素执行操作，不返回新数组
tasks.forEach(function(t) { console.log(t.text); });
// 依次输出: "买牛奶" "写作业" "跑步"
注意区分： filter 返回新数组（不修改原数组）， find 返回第一个匹配的元素， forEach 不返回任何值，只执行操作。

9localStorage — 让数据不丢失

核心概念: 浏览器的"永久存储"

默认情况下，刷新页面后所有 JavaScript 变量都会重置。 localStorage 是浏览器提供的存储空间， 数据会一直保留，除非用户手动清除。 

var STORAGE_KEY = "lmm-todo-tasks";

// 保存（只能存字符串，所以用 JSON.stringify 转换）
function saveTasks() {
  localStorage.setItem(STORAGE_KEY, JSON.stringify(tasks));
  // JSON.stringify:  数组/对象 → 字符串
}

// 加载（读出来是字符串，用 JSON.parse 转回对象）
function loadTasks() {
  var raw = localStorage.getItem(STORAGE_KEY);
  if (raw) {
    tasks = JSON.parse(raw);
    // JSON.parse:  字符串 → 数组/对象
  }
}

// 删除
localStorage.removeItem(STORAGE_KEY);

// 全部清空（慎用）
localStorage.clear();
JSON.stringify / JSON.parse 是什么？ 它们是 JavaScript 内置的"翻译器"。stringify 把 JS 对象翻译成字符串（存）， parse 把字符串翻译回 JS 对象（读）。这是数据持久化最基础的模式。
容量限制：localStorage 每个域名约 5-10MB， 不适合存大量数据。大规模应用用 IndexedDB 或后端数据库。

10完整数据流 — 从输入到持久化的全过程

核心概念: 理解"状态驱动渲染"模式

整个应用围绕一个核心模式运行：修改数据 → 保存 → 重新渲染。 这叫做"状态驱动渲染"——界面永远是数据的映射。 

/* ==========================================
   核心循环（每个操作都走这个流程）
   ========================================== */

// 添加任务时的完整流程:
function addTask(text) {
  // 步骤1: 修改数据（往数组里 push 新对象）
  tasks.push({ id: ..., text: text, completed: false });

  // 步骤2: 持久化（存到 localStorage）
  saveTasks();

  // 步骤3: 重新渲染（根据新数据重画界面）
  render();
}

// render() 函数做的事:
function render() {
  // 1. 根据 currentFilter 筛选数据

  // 3. 逐条创建 li 元素插入（forEach + createElement）

  // 4. 更新计数
  updateCount();
}
三个核心原则：
① 数据是唯一的真相来源 — 界面永远从数据推导出来
② 任何修改都先改数据，再刷界面 — 保持一致性
③ 保存跟在修改之后 — 防止刷新丢失数据
